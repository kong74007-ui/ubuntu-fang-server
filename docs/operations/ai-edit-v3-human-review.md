# AI Edit V3 双人盲审操作规程

本规程用于 Phase E 的 20 条成片验收。它不是上线授权；评审、合并、部署和真实测试环境调用仍是独立步骤。

## 1. 生成盲审包

盲审源清单必须包含冻结的 `case_01` 至 `case_20` 共 20 条记录。运行：

```powershell
python scripts/ai_edit_v3_acceptance.py blind-export --source review-source.json --output blind-package.json
```

导出器采用字段白名单，只保留 `case_id`，并将文件名重新编号为 `blind_001.mp4` 至 `blind_020.mp4`。源文件名、渲染器、模板、提示词、Provider、输入模式及实现布局不得进入盲审包。原文件与盲文件的复制映射必须单独受控保存，不交给评审员。输出文件采用独占创建；已有文件不会被覆盖。

## 2. 评审人员与独立性

- Reviewer 1 与 Reviewer 2 必须是不同自然人，使用不同 `reviewer_id`，独立完整观看同一批 20 条成片。
- 不得互看评分，不得由生成、渲染或自动质检程序冒充评审员。
- 只有两人的个人通过结论对某条成片不一致时，该条才交给 Reviewer 3。Reviewer 3 必须是第三个自然人，且只评争议条目。
- 重复对象、重复 ID、非法 ID、缺失或多余案例全部按无效评审处理。

## 3. 评分格式

评审 JSON 必须符合 `tests/fixtures/ai_edit_v3/human-review.schema.json`。八个维度固定为：事实准确、素材相关、前三秒钩子、叙事节奏、布局清晰、字幕可读、声音质量、视觉一致性。

每项只能填写整数 `0`、`1` 或 `2`。每个分数必须同时填写：

- 与该分数完全一致的冻结锚点原文；
- 至少 8 个字符的具体观察说明。

运行时验证器会再次检查分数与锚点是否匹配；Schema 通过不代表运行时验证必然通过。

## 4. 通过规则

- 个人通过：总分至少 13/16，且事实准确、素材相关、字幕可读、声音质量均不为 0。
- 无第三人：两人平均分至少 13，且两人的四个关键维度均不为 0。
- 有第三人：三人平均分至少 13，至少两人的个人结论通过，且三人的四个关键维度均不为 0。
- 整批通过：20 条中至少 16 条可发布。

## 5. 创意分布门槛

整批场景必须绑定当前冻结的 HyperFrames 组件注册表 SHA，并只使用注册表中的 canonical 布局与结构变体 ID。至少使用 8 种布局；每种被使用的布局至少出现 2 个结构变体；任一布局不得超过全部场景的 35%。连续使用同一布局不得超过 2 场，除非第三场及以后逐场记录允许值：`speaker_continuity`、`step_sequence` 或 `evidence_hold`。

“换颜色但结构相同”按同一布局与同一变体计算。机械模板包即使技术质检通过，也不得进入可发布结果。

## 6. 留痕

保留盲审包 SHA、三份评审 JSON SHA、评审员 ID、争议案例集合、逐条判定理由及创意分布报告。评审文件不得包含签名播放 URL、密钥、提示词或供应商请求内容。
