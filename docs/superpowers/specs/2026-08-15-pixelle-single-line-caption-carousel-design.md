# Pixelle 单行字幕轮播设计

## 目标

解决文案成片中单个镜头字幕过长、占据多行并遮挡画面的问题。

本次只修改字幕的分段、音频对齐和显示方式：

- 每次只显示一行字幕。
- 字幕按语音进度依次轮播。
- 字幕切换点使用每段真实音频时长，保持字幕与声音对齐。
- 保留当前模板的字体、字号、字重、颜色、描边、阴影、位置、标题、素材、排版和其他动效。
- 不增加分镜，不增加图片或视频素材生成次数，不改变成片总文案。

## 非目标

- 不重新设计模板。
- 不新增字幕样式选项。
- 不修改标题、主视觉或素材生成策略。
- 不使用字号自动缩小、文本截断或省略号来容纳长字幕。
- 不改变任务并发、重试、计费和部署配置。

## 当前问题

当前每个分镜将整段 `narration` 直接传给模板并生成一次静态画面。中文旁白可能包含几十个字，因此模板会把整段内容自动换成多行。由于画面只渲染一次，无法在同一镜头中随语音进度更新字幕。

## 用户可见行为

一个原有分镜仍然只使用原来的一张图片或一段视频。该分镜的旁白会拆成若干短句，例如：

```text
所以轩和堂做这件事，
并不是为了追风口，
是为了让门店效果可验证、
服务标准化、成本可控。
```

播放时只显示当前正在朗读的短句。上一句结束后，字幕在同一位置直接替换为下一句，画面和模板其他元素不重新布局。

## 字幕拆分规则

服务端新增中文友好的字幕切分器，输入完整旁白，输出有序字幕段。

1. 优先按句号、问号、感叹号、分号、冒号和换行切分。
2. 句子仍过长时，再按逗号、顿号和空格切分。
3. 仍过长时按显示宽度切分，不丢字符，不改变原始顺序。
4. 中文字符、全角字符按 2 个显示单位计算；ASCII 字母、数字和半角符号按 1 个显示单位计算。
5. 默认单条上限为 28 个显示单位，约等于 14 个中文字符。标点保留在对应字幕段中。
6. 合并过短片段时不得超过单条上限。
7. 切分后拼接并忽略切分处新增的空白，必须与原旁白内容一致。

该规则保证常用模板在现有字号下保持单行，同时不依赖浏览器临时缩小字体。

## 音频与时间轴

### 公共音色

Pixelle 对每个分镜先拆分字幕，再逐条调用现有 TTS。每条音频生成后使用媒体探测读取真实时长，按顺序拼接成该分镜的旁白音轨。

字幕时间点由真实时长累加得到：

```text
cue_1: 0 -> duration_1
cue_2: duration_1 -> duration_1 + duration_2
...
```

不按字数比例估算时间，也不使用固定轮播间隔。

### 个人音色

主网站使用用户已有的个人音色能力。每个原有分镜先按同一规则拆分字幕，再逐条生成个人音色音频并上传给 Pixelle。Pixelle读取每条实际音频时长并建立相同的字幕时间轴。

个人音色失败仍沿用当前任务失败和错误返回规则，本功能不增加公共音色回退，避免未经用户选择更换声音。

## 接口设计

扩展现有 `narration_segments`，允许一个原有分镜携带多个字幕音频：

```json
{
  "text": "完整分镜旁白",
  "cues": [
    {
      "text": "第一条单行字幕，",
      "audio_asset_id": "asset-1"
    },
    {
      "text": "第二条单行字幕。",
      "audio_asset_id": "asset-2"
    }
  ]
}
```

兼容规则：

- 旧请求中的 `{text, audio_asset_id}` 继续有效，并视为只有一个 cue。
- `cues` 和顶层 `audio_asset_id` 不得同时提供。
- `cues` 必须非空并保持提交顺序。
- 每个 cue 必须有非空 `text` 和有效 `audio_asset_id`。
- 资产租约、清理和失败释放覆盖所有嵌套的 `audio_asset_id`。
- 一个 `narration_segments` 项仍对应一个分镜，cue 数量不会影响素材生成数量。

## 渲染设计

### 图片分镜

原图片、标题、背景、排版和模板样式只生成一次。渲染阶段为每个 cue 生成对应时长的画面片段，复用同一图片和同一模板，只替换字幕文本，随后按顺序拼接。

### 视频分镜

原视频素材只生成一次。渲染阶段按照 cue 时间点连续截取该视频的对应区间，并叠加当前字幕。不会为每条字幕重新请求视频素材，也不会从视频开头重复播放。

### 单行约束

模板字幕节点仅增加 `white-space: nowrap` 等单行约束，不覆盖现有字体相关 CSS。切分器负责保证文本长度，不使用横向压缩、字号缩放、裁切或滚动字幕。

字幕在 cue 边界直接替换，不新增淡入淡出，避免改变现有模板动效和造成相邻字幕重叠。

## 数据模型

每个渲染分镜增加内部 cue 列表：

```text
CaptionCue
  text
  audio_path
  duration
  start_time
  end_time

Frame
  existing fields...
  caption_cues[]
```

`Frame` 仍是素材和模板的最小单位，`CaptionCue` 只控制该 Frame 内的字幕和音频。

## 失败处理

- 任一 cue 音频生成失败时，沿用当前音频失败策略，不输出缺字或静音错位的视频。
- 音频探测失败时任务返回明确错误，不回退到按字数估算。
- 字幕切分后为空或内容校验不一致时，在渲染前失败。
- 素材生成成功但字幕阶段失败时，沿用现有任务清理规则。
- 单个分镜最多接受 20 个 cues，超过时拒绝请求并返回参数错误，防止异常文案制造超大渲染任务。

## 测试与验收

### 单元测试

- 中文、英文、数字和中英混排均不超过显示宽度上限。
- 标点优先切分，超长无标点文本可以安全切分。
- 切分前后内容一致，无漏字、重复字或乱序。
- 短旁白保持一个 cue。
- 真实音频时长正确累加为 cue 起止时间。
- 旧版单音频请求仍可解析和执行。
- 嵌套音频资产全部进入租约、释放和清理流程。

### 集成测试

- 公共音色：同一分镜内多条单行字幕按实际语音切换。
- 个人音色：网站生成的多条音频与字幕逐条对应。
- 图片模板和视频模板均只生成一个素材，不因 cue 数增加素材请求。
- 视频分镜连续播放，不在字幕切换时跳回开头。
- 所有现有模板的字体、字号、颜色、描边、阴影、位置和标题保持不变。
- 竖屏输出中任何时刻只出现一行正文字幕，且相邻字幕不重叠。
