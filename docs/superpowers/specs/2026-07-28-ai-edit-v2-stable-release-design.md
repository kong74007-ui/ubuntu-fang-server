# AI 智能剪辑 V2 第一版稳定发布设计

## 1. 文档目的

本文冻结 AI 智能剪辑 V2 在测试环境的第一版可交付范围。它是完整 V2 设计的稳定落地切片，不替代 `2026-07-27-ai-edit-v2-design.md`。

第一版目标是让用户选择平台口播视频、上传外部视频或上传音频后，直接获得一条通过质检的 1080p MP4。系统优先稳定出片，同时保留内容驱动的字幕、重点卡片、素材插入、BGM 和音效差异，不把每条视频做成同模板换色。

本版本只部署到测试环境。旧“一键剪辑”、PR #20 V1、生产服务和生产数据库保持不变。

## 2. 冻结范围

### 2.1 本版本包含

- 三类主输入：平台已生成口播视频、外部上传视频、音频。
- 三种创作入口：用户自然语言要求、平台稳定模板、AI 根据内容自动判断。
- 两个素材窗口：必须使用素材、参考使用素材；均支持图片、视频和音频。
- Fun-ASR 逐字、逐句时间戳。
- 平台原口播文案与 ASR 时间轴的确定性对齐。
- 外部视频或音频的 ASR 文本，以及仅限断句、标点修复的文本清理。
- Qwen 输出受约束的 `edit-plan 2.0` 语义导演方案。
- 素材优先级：本次上传、用户历史素材库、平台公共素材库、GPT 图片生成。
- Shotstack 标准剪辑、字幕、重点卡片、图片/视频 B-roll、基础转场和最终合成。
- ElevenLabs 生成无歌词 BGM、转场音效和重音音效。
- FFprobe 检测、必要时 FFmpeg 标准化、对白避让、混音和质检。
- 成片转存私有 COS、写入用户视频资产库、网页播放、MP4 下载和站内任务通知。
- 动态报价、按上限预扣、按实际价格结算、退还差额、未交付合格成片时全额退款。

### 2.2 本版本不包含

- Remotion、Remotion Lambda、HyperFrames 和 video-shotcraft 运行时。
- 自由代码 MG、任意 HTML/JS、AI 动态生成渲染代码。
- AI 短视频素材生成。
- 重新生成人物口播画面。
- AI 补录、克隆音色补录和通用配音补录。
- 内容安全审核。
- 用户在线编辑时间线。
- 生产环境部署。

上述能力保留为后续版本，不得以隐藏路径进入第一版任务。

## 3. 推荐架构

第一版采用“AI 导演、确定性解析、Shotstack 稳定渲染”的单渲染路线：

```text
用户输入
  -> 权限、归属、格式、容量、时长校验
  -> 报价与上限预扣
  -> FFprobe/FFmpeg 标准化
  -> Fun-ASR 时间戳
  -> 原文对齐或外部文本清理
  -> Qwen edit-plan 2.0
  -> 素材槽位解析
  -> GPT 图片补缺
  -> ElevenLabs BGM/SFX
  -> Shotstack render graph
  -> Shotstack 渲染
  -> 下载、FFmpeg 混音/后处理、完整质检
  -> 私有 COS 与用户视频资产库
  -> 实际结算与站内通知
```

网站主服务器负责任务编排、权限、计费、状态和轻量媒体处理，不执行 AI 生成代码。所有第三方调用通过独立 Provider 适配器完成，业务层不直接依赖供应商字段。

## 4. 文本与时间轴真值

### 4.1 平台口播视频

- 原口播文案是字幕和事实文本的唯一真值。
- Fun-ASR 只提供逐字和逐句时间戳。
- 确定性对齐算法将原文映射到 ASR 时间轴。
- 品牌名、产品名、数字、价格和专有名词以原文为准。
- 对齐置信度不足时不得让 Qwen 猜测正文；任务进入可诊断失败或受控人工检查状态。

### 4.2 外部视频和音频

- Fun-ASR 同时提供文本和时间戳。
- 文本清理只允许恢复标点、断句和明显口头重复，不得改变事实或原意。
- Qwen 导演不能改写字幕正文。

### 4.3 字幕生成

- 字幕正文由确定性文本时间轴生成，不使用 Shotstack 中文自动识别。
- 使用随项目发布并经验证的中文字体，第一选择为 Noto Sans SC。
- 字幕必须在安全区内，不能超出画面、出现乱码、豆腐块或遮挡人物关键面部区域。

## 5. `edit-plan 2.0` 边界

Qwen 只输出语义导演方案，包括场景、意图、布局类型、标题、素材槽位、转场语义、字幕样式、BGM 情绪和音效 cue。Qwen 不得输出：

- COS key、签名 URL、数据库 ID。
- Shotstack track、clip、effect 等供应商字段。
- 供应商密钥、模型凭证或任意外部 URL。
- HTML、JavaScript、Remotion、HyperFrames 或自由代码。

服务端必须以 JSON Schema 校验模型输出。校验失败允许基于明确错误修复，最多 2 次；仍失败则任务失败并全额退款。

## 6. 素材解析

素材槽位按以下顺序解析：

1. 用户本次上传素材。
2. 当前用户历史素材库。
3. 平台公共素材库。
4. GPT 图片模型生成。

“必须使用”素材使用率必须为 100%。参考素材由 AI 判断是否使用，但必须记录采用或排除原因。上传素材优先，特别是产品、门店、招商广告和品牌资产；AI 不得用生成图片替换用户明确要求必须使用的真实产品素材。

AI 图片生成后必须先写入 COS，形成内部资产记录，再在提交 Shotstack 前生成短期签名地址。签名 URL 不写入持久化导演方案。

第一版没有 AI 短视频生成。视频素材不足时，允许使用相关图片加受控缩放、平移或裁切形成 B-roll；不允许伪造产品外观、功效或场景事实。

## 7. BGM、音效与混音

### 7.1 ElevenLabs Provider

- BGM 模型：`music_v2`。
- 音效模型：`eleven_text_to_sound_v2`。
- 人声主导视频强制生成无歌词音乐。
- 音乐提示只描述情绪、节奏、结构、时长和无歌词要求。
- 音效只用于语义转折、镜头切换、重点卡片或重音，不按固定间隔堆叠。

### 7.2 声音规则

- 人声始终是主音轨。
- BGM 自动 ducking，不得遮盖对白。
- 品牌、产品、数字、价格和关键信息区间不放遮盖性强的音效。
- 相邻音效过密时合并或择优，避免噪声化。
- 原视频存在合适 BGM 时，AI 可决定保留、降低或替换，但不能损坏人声。
- 混音必须通过响度、削波、静音和音画时长一致性检查。

## 8. Shotstack 稳定组件

第一版只开放经过审核的组件族：

- `basic_caption`：中文字幕与关键词强调。
- `basic_card`：标题、问题、数字、结论和重点信息卡片。
- `broll_image`：图片插入、画中画、分屏和受控镜头运动。
- `broll_video`：用户或素材库视频插入。
- `standard_transition`：硬切、淡入淡出和少量审核过的标准转场。
- `audio_bed`：BGM、转场音效和重音音效。

同一模板只统一字体、色彩关系、组件语言和节奏范围，不固定场景数量、标题内容、素材坐标或每条视频的布局顺序。Qwen 根据内容实例化组件，使同模板视频保持同风格但不完全相同。

Shotstack 适配层只接收已解析的 `resolved_plan`，生成 `render_graph`。提交必须有幂等引用；网络超时且提交结果不确定时先查询已有任务，不得盲目重复创建可能收费的渲染。

Webhook 只作为状态变化提示。服务端收到回调后按供应商任务 ID 主动回查，回调正文中的状态和下载 URL 不直接作为真值。第一版也必须支持没有 Webhook 时的主动轮询。

## 9. 比例、时长与输出

- 上传视频时，默认沿用主视频比例；允许用户选择受支持比例。
- 只有音频或参考图片时由用户选择比例，默认横屏 16:9。
- 输出为单条 1080p MP4。
- 目标时长由 AI 根据内容决定；用户指定目标时长时允许内容重剪。
- 例如 60 秒输入剪成 30 秒时，系统允许删除重复、铺垫和低信息密度段落，但必须保留核心论点、必要事实和语义连续性，并记录删除区间。
- 当前允许 AI 进行内容级删减，该策略标记为后续可复核产品决策。

## 10. 状态、时间与并发

第一版至少包含以下可观察状态：

```text
quoted -> held -> queued -> normalizing -> transcribing -> aligning
-> directing -> resolving_materials -> generating_media -> rendering
-> postprocessing -> quality_checking -> storing -> settling -> completed
```

失败进入 `failed`，降级记录在独立字段，不伪装为完整能力成功。

- 正常目标耗时：5 至 15 分钟，根据输入时长、生成素材数量和供应商排队动态变化。
- 任务硬上限：45 分钟。
- 成片质检发现明确可修复问题时，允许增加最多 15 分钟修复预算。
- Qwen、GPT 图片、ElevenLabs 和 Shotstack 单阶段最多重试 2 次。
- 测试环境 Worker 并发默认 5，可配置到 10。
- 并发限制以真实外部配额、服务器 CPU/内存和任务延迟测试结果为准，不承诺固定吞吐。
- 每个阶段保存检查点；服务重启后从最近可验证检查点恢复，不能重复扣费、退款、入库或提交供应商任务。

## 11. 降级和失败策略

- 非必须 AI 图片失败：使用已有合格素材或回到人物主画面，并记录降级。
- BGM 失败：允许无新 BGM 出片，并记录降级。
- 单个非必须音效失败：跳过该音效，并记录降级。
- 必须使用素材缺失、损坏或无法合法放入时间线：任务失败并全额退款。
- 字幕真值无法可靠建立：任务失败，不让模型猜测。
- Shotstack 两次重试后仍失败：任务失败并全额退款。
- 超过总时间预算且没有通过质检的成片：任务失败并全额退款。
- 任何已成功交付且通过质检的降级成片，页面必须向用户显示降级说明。

## 12. 报价和结算

创建任务前返回价格区间，按上限预扣点数。报价至少考虑：

- 输入和预计输出时长。
- 素材数量与标准化成本。
- 预计生成图片数量。
- BGM 和音效生成数量。
- Shotstack 渲染时长。
- 质检和修复预算。

完成后按实际使用量结算并退还差额。预扣、实际结算、退差额和全额退款都必须使用唯一交易键与条件更新保证幂等。未交付通过质检的成片一律全额退款，不向用户追加超过预扣上限的费用。

## 13. 成片质检

### 13.1 内容硬门槛

- 平台口播字幕与原文一致，外部内容不改变原意。
- 品牌名、产品名、数字和价格正确。
- 必须素材使用率 100%。
- 无虚构的产品外观、功效、门店或招商事实。
- 内容删减后语义连续，没有前后指代断裂。

### 13.2 技术与画面硬门槛

- MP4 可解码、可拖动播放、存在视频流和音频流。
- 输出分辨率符合目标比例的 1080p 规格。
- 输出时长与计划和音轨时长在允许误差内。
- 无持续黑帧、空白帧、严重花屏或错误旋转。
- 字幕不越界、不乱码、不出现豆腐块。
- 图片和视频素材不严重拉伸，不暴露短期签名 URL。

### 13.3 声音硬门槛

- 人声清楚、无削波、无异常静音。
- BGM 和音效不压人声。
- 音轨与画面时长一致。
- 关键对白区间没有遮盖性音效。

明确问题允许在修复预算内针对性重渲染；不能修复则失败退款，不交付问题成片。

## 14. 用户界面与接口

用户界面提供：

- 创作方式、主输入、必须素材、参考素材、目标比例和目标时长。
- 报价区间和上限预扣确认。
- 任务阶段、预计剩余时间、降级状态和失败原因。
- 成片播放器、MP4 下载、实际结算、退还差额和资产库入口。

第一版沿用独立 V2 边界：

- `POST /api/v2/edit/quote`
- `POST /api/v2/edit/jobs`
- `GET /api/v2/edit/jobs/{job_id}`
- `POST /api/v2/edit/jobs/{job_id}/retry`
- `GET /api/v2/edit/capabilities`
- Shotstack Webhook 使用独立鉴权与事件去重接口。

用户不选择供应商，也不看到 Shotstack、Qwen、OpenAI 或 ElevenLabs 名称。

## 15. 配置与密钥

## 16. 验收标准

上线测试站前至少完成：

1. 自动化测试覆盖归属校验、扣款/退款幂等、时间轴对齐、Qwen Schema、素材优先级、必须素材、Provider 重试、Shotstack 回调乱序、重启恢复和 COS 入库。
2. 使用脱敏 fake Provider 完成完整流水线测试，不访问真实供应商。
3. 分别对 DashScope、OpenAI 图片、ElevenLabs 音乐、ElevenLabs 音效、Shotstack 和 COS 做最小真实连通性测试。
4. 至少完成平台口播、外部视频、音频三类真实端到端样本各 1 条。
5. 真实样本全部满足内容、画面、声音和技术硬门槛。
6. 必须素材使用率 100%，失败退款仅执行一次，成功任务仅结算一次并只入库一次。
7. 页面可查看任务进度、播放成片、下载 MP4，并能在用户视频资产库找到成片。
8. 旧“一键剪辑”和现有视频生成流程回归通过。
9. 只从已推送且通过 CI 的提交部署测试环境；禁止服务器热改。

第一版通过不代表获准部署生产环境。生产上线必须在真实样本数量、并发、费用、供应商配额、故障恢复和用户体验达到独立验收后另行批准。

## 17. 后续版本

第一版稳定运行并积累质量数据后，再独立评估：

- HyperFrames 或 Remotion 的复杂信息动画、动态图表和自由布局路线。
- video-shotcraft 的镜头创作方法自动化。
- AI 短视频素材。
- 自由代码 MG 沙箱。
- AI 少量改写与音色补录。
- 更多平台模板和组件。
- 内容安全审核。

后续能力不得修改第一版 `edit-plan 2.0` 的语义边界；新增渲染器应通过服务端适配层接入。
