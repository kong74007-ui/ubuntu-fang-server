# AI Edit V2 数字化 IP 主体资产设计

## 目标

AI Edit V2 第一步的账号内视频卡片只展示当前账号通过“数字化 IP”口播流程生成并已完成的视频。普通上传视频、AI 视频、历史剪辑成片和其他视频类型不得进入该列表。页面原有“上传视频”和“上传音频”入口保持不变。

## 方案

以服务端为权威边界，不依赖标题、封面、文件名或前端隐藏规则。候选资产必须同时满足：

- `video_assets.username` 等于当前登录账号；
- `video_assets.mode` 为 `text` 或 `audio`；
- 对应原始任务属于同一账号，`jobs.kind` 为 `video`；
- 原始任务 payload 的 `mode` 为 `text` 或 `audio`，并与资产模式一致；
- 资产状态已完成，且存在可读取的视频文件引用。

列表接口只返回通过上述校验的记录，并给每条记录返回固定分类 `asset_type=digital_ip`。导入接口复用同一判定，防止客户端通过猜测资产 ID 绕过列表限制。前端只渲染 `asset_type=digital_ip` 的项目，并把文案改为“数字化 IP 口播视频”。

## 失败策略

来源无法确认时失败关闭：记录不进入列表，导入请求返回不可用。数据库读取异常保持现有接口错误处理，不回退到普通视频资产列表。

## 验收

- 当前账号已完成的 `text`、`audio` 数字化 IP 视频可见并可导入；
- 其他账号、其他 mode、非 `video` 任务、payload mode 不一致、未完成或缺少视频文件的记录不可见且不可导入；
- 上传视频、上传音频仍可作为新主体；
- 页面不会调用通用 `/api/gen/video/assets` 作为主体列表来源。
