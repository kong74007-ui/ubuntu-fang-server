# AI Edit V2 第一版禁用可选音乐与音效设计

## 目标

第一版稳定剪辑只使用输入视频或音频中的原始声音，不生成 BGM，不生成转场、重音或环境音效。ElevenLabs 不再是第一版提交任务的硬依赖，也不应阻塞 Shotstack 稳定剪辑上线。

## 行为边界

- 导演方案进入执行边界时，`music_policy` 固定为 `none`，`sfx_policy` 固定为 `none`。
- 音频计划必须输出 `bgm: null`、`sfx: []`，不得调用 ElevenLabs Provider。
- 原视频或原音频中的人物声音继续保留，并沿用现有响度处理和成片质检。
- 对外能力响应返回 `optional_audio: false`。
- 第一版生产就绪检查不要求 `ELEVENLABS_API_KEY`，但 ElevenLabs Provider 和现有测试代码保留，便于后续通过独立功能开关恢复。
- 报价与实际结算中音乐和音效用量均为零，不产生对应供应商费用。
- 不删除服务器中已经保存的测试密钥；禁用状态下运行链路不得读取或调用它。

## 实现方案

采用“稳定版能力开关”而不是删除模块：

1. 在稳定运行时声明可选音频能力关闭。
2. 导演约束和模板输出统一收敛到 `none/none`。
3. 生产依赖检查移除 ElevenLabs 硬门槛。
4. 生成媒体阶段对空音频计划走显式无生成分支，继续生成只含原声的母带音轨。
5. API 能力、计费记录和任务检查点明确记录未启用，避免静默降级。

## 错误处理

- 若模型仍返回 BGM 或 SFX 请求，确定性规范化为 `none/none`，不调用供应商。
- 若执行边界收到非空 `bgm` 或 `sfx`，任务以稳定错误码拒绝，避免配置漂移后意外付费。
- 原声缺失、损坏或质检不通过仍沿用现有失败与全额退款逻辑。

## 验收标准

- 删除或留空 `ELEVENLABS_API_KEY` 时，其他稳定依赖齐全即可通过生产就绪检查。
- 平台视频、外部视频、纯音频三种输入均不会产生 ElevenLabs HTTP 请求。
- 输出音频计划始终为 `bgm: null`、`sfx: []`。
- 能力接口返回 `optional_audio: false`。
- 计费证据中 `music=0`、`sfx=0`。
- 现有 Shotstack、字幕、素材匹配、质检、退款和交付行为不受影响。
- 完整 `test_ai_edit_v2*.py` 测试集通过。

## 后续恢复

未来恢复音乐和音效时，通过独立配置开关重新开放导演策略、Provider 就绪检查和计费项，不改变现有任务协议版本，也不自动影响已创建任务。
