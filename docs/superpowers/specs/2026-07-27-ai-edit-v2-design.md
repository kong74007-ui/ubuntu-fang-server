# AI 智能剪辑 V2 最终设计规格

## 1. 文档状态与产品目标

本文定义黄雀传媒测试环境的新模块“AI智能剪辑 V2”。它不是单一口播模板工具，而是面向多内容类型的通用AI视频剪辑与创作系统，首期支持数字人口播、真人口播、纯音频、产品、旅游美食、访谈课程，并通过扩展内容类型、平台模板和渲染组件持续演进。

V2与测试站现有“一键剪辑”并行存在，不替换、不迁移、不复用旧模块数据库，也不继续修改PR #20的旧实现。V2使用独立页面、API、数据库、队列、Worker、渲染路由和日志命名空间。

本阶段只允许开发和部署测试环境，不进入生产服务器。内容安全审核不属于本阶段。本文描述的是最终产品能力，但实施必须分阶段完成，每个阶段均有独立测试、提交和回滚边界。

## 2. 产品原则

- 用户不编辑时间线，不面对专业剪辑参数。
- 每个任务由AI完成导演、素材选择、声音设计、渲染和质检，只交付一条最优成片。
- 可以在正式渲染前生成低成本关键帧预览用于系统自检，但不为用户并行渲染多条完整候选片。
- 质量优先，同时必须稳定交付；开放创作失败时允许降级到风格相近的稳定模板。
- 模板保持统一视觉语言，但场景、分镜、布局、素材位置、节奏和动画必须随内容改变，禁止机械复制。
- 开放生成允许AI为每条视频产生新布局、MG和受控动画代码，优秀结果经管理员审核后可沉淀为模板或组件。
- 能通过第三方API稳定完成的环节优先API化；网站主服务器只负责任务编排、权限、计费和状态，不执行AI生成代码或重型渲染。
- 普通用户不能上传模板代码、发布公共模板或执行自定义代码。

## 3. 隔离边界

### 3.1 保持不变

- 现有“一键剪辑”入口、接口、任务、数据和成片保持不变。
- PR #20的旧剪辑协议与代码保持不变。
- 旧 `ai_edit.db`、历史HyperFrames任务和历史成片不迁移到V2。
- 生产数据库、生产密钥、生产域名和生产服务不在本阶段操作范围内。

### 3.2 V2独立资源

- 开发分支：`codex/ai-edit-v2`，从最新 `main` 创建。
- 页面：`site/workbench/ai-edit.html`，用户侧名称为“AI智能剪辑”。
- API前缀：`/api/v2/edit/*`。
- 数据库：`ai_edit_v2.db`。
- 队列：AI Edit V2专用队列。
- Worker：首期配置5至10个并行处理槽，按实测和供应商限额调整。
- 日志前缀：`[ai-edit-v2]`。
- 重型渲染：Shotstack API与隔离Remotion云函数/托管渲染服务。

公共文件只允许最小增量接线，例如注册V2能力、API处理器和工作台入口；不得把V2业务逻辑写入 `core.py`、旧页面或旧剪辑模块。

## 4. 三种创作入口

### 4.1 用户自然语言要求

用户用自然语言描述目标、受众、节奏、重点、风格、参考作品或特殊要求。AI补全缺失的导演信息并形成完整方案。用户不需要理解镜头、MG或音频术语。

### 4.2 平台模板

管理员发布已审核的平台模板。模板定义稳定的视觉语言、组件族、字体、色彩、动画节奏和声音风格，但不能固定每条视频的场景数量、分镜、布局和素材坐标。模板实例化必须由内容驱动。

可稳定参数化的完整Remotion/Shotcraft项目包优先接入。实验性、强绑定单片内容或不能安全参数化的组件，必须先通用化并通过管理员审核，才能成为平台模板。

### 4.3 AI开放生成

AI根据每条内容自由设计布局、MG、动态图表、编辑拼贴、动画和声音方案。开放生成可以产生任务专属的受控Remotion动画代码，但代码只能在隔离沙箱和托管渲染环境中验证与执行。

开放生成失败时自动修复最多2次；仍失败则降级到风格相近的稳定平台模板，并记录原因。系统持续统计降级率，降级成片不得冒充开放创作成功。

## 5. 输入与用户素材

### 5.1 主输入

用户可选择自己在平台生成的视频/音频资产，或上传外部视频/音频。支持数字人口播、真人口播、纯音频和其他内容源。

画面比例规则：

- 存在主视频时，默认沿用主视频比例。
- 无主视频、仅图片/音频/参考素材时，由用户选择比例，默认16:9。
- 首期输出仅支持9:16和16:9，统一1080p。

主视频或主音频最长10分钟。第一阶段只处理中文内容。

### 5.2 两个上传窗口

“必须使用”窗口：

- 最多10个素材。
- 支持图片、视频和音频。
- 所有通过格式和归属校验的必须素材，最终成片使用率必须达到100%。
- 若必须素材无法安全使用，任务不得静默完成，必须要求用户调整或进入失败状态。

“参考使用”窗口：

- 最多10个素材。
- 支持图片、视频和音频。
- 每个素材进一步标记为“可直接使用”或“仅作风格参考”。
- AI保留质量判断权，可排除重复、模糊、无关、低质量或构图不适合的参考素材，并记录排除原因。
- “仅作风格参考”的素材不得出现在成片中。

### 5.3 容量限制

- 主视频：最大500MB。
- 补充视频：单个最大200MB。
- 图片：单张最大15MB。
- 音频：单个最大50MB。
- 单任务全部上传文件合计最大1GB。

上传成功的素材进入当前用户历史素材库并按账号隔离。参考视频分析出的节奏、布局、字幕、转场、配色和音乐感觉仅用于当前任务，任务结束后删除，不保存为个人风格。

### 5.4 参考视频学习边界

系统可以学习参考视频的抽象特征：节奏、镜头密度、布局变化、字幕感觉、转场强度、配色关系、音乐情绪和声音动态。不得复制参考视频的素材、文案、Logo、音乐、人物身份或可识别品牌资产。

## 6. 用户流程

1. 用户选择创作入口、主输入、必须素材、参考素材和可选目标时长。
2. 服务端校验登录状态、账号归属、文件格式、容量、时长和并发限制。
3. 报价服务根据输入时长、生成素材类型、渲染复杂度和供应商路线显示价格区间。
4. 用户确认后，系统按价格上限预扣点数并创建幂等任务。
5. 任务进入独立队列；前端单独显示排队时长，排队不计入处理时长。
6. FFprobe检测媒体，必要时用FFmpeg标准化、降噪、去混响、响度统一和人声增强。
7. fun-asr输出分句和逐字时间戳；平台口播执行原文对齐。
8. AI导演分析语义结构、可删片段、段落顺序、目标时长、素材需求、声音设计和渲染复杂度。
9. 素材解析器优先匹配用户素材，缺失时生成图片、短视频、图标插画、动态图表、BGM和音效。
10. 自动渲染路由把常规片段交给Shotstack，把复杂MG和自由布局交给隔离Remotion。
11. 各分段统一合成为1080p MP4，并执行完整技术、内容、声音和视觉质检。
12. 已产生成片但质检失败时，只针对明确问题进入修复阶段。
13. 质检通过后按实际平台计费规则结算并退还预扣差额。
14. 成片转存COS并进入用户视频资产库。
15. 用户通过网页播放、MP4下载和站内任务状态通知获得结果。

## 7. 推荐架构：AI导演＋混合渲染

用户已选择Shotstack与Remotion混合渲染方案，用户界面不暴露渲染器选择。

```text
输入与用户要求
-> 权限/格式/报价
-> 媒体标准化
-> ASR与原文对齐
-> AI导演 edit-plan 2.0
-> 素材解析与全类型生成
-> Render Graph路由
   -> Shotstack常规场景
   -> 隔离Remotion复杂场景
-> Shotstack统一编排/最终合成
-> FFmpeg后处理与质检
-> 实际结算
-> COS与视频资产库
```

Shotstack负责：

- 常规字幕。
- 素材插入。
- 基础信息卡片。
- B-roll。
- 标准转场。
- 混合场景的最终时间线编排与合成。

Remotion云函数/托管渲染负责：

- 复杂信息动画和MG。
- 动态图表和数据可视化。
- 编辑拼贴。
- 自由创意布局。
- 平台参数化高级模板。
- AI生成的任务专属动画代码。

复杂场景先由Remotion输出符合统一规格的片段，Shotstack再与常规场景、主音轨、字幕和声音设计统一编排。最终输出始终为单条1080p MP4。

## 8. 模块划分

- `ai_edit_v2_api.py`：鉴权、上传、报价、提交、查询、继任任务和Webhook入口。
- `ai_edit_v2_store.py`：V2数据库、状态、阶段尝试、素材关系、报价和事件去重。
- `ai_edit_v2_pipeline.py`：状态机、时间预算和完整任务编排。
- `ai_edit_v2_schema.py`：提交参数、导演方案和Render Graph白名单校验。
- `ai_edit_v2_media.py`：FFprobe、FFmpeg、临时文件和声音预处理。
- `ai_edit_v2_asr.py`：fun-asr提交、轮询和结果归一化。
- `ai_edit_v2_alignment.py`：平台原文与ASR时间戳确定性对齐。
- `ai_edit_v2_director.py`：Qwen导演提示词、结构化输出和一次结构修复。
- `ai_edit_v2_reference.py`：参考视频抽象风格分析和任务结束清理。
- `ai_edit_v2_assets.py`：素材质量判断、四级匹配和全类型生成。
- `ai_edit_v2_audio.py`：BGM、音效、对白避让和声音增强方案。
- `ai_edit_v2_router.py`：逐场景选择Shotstack或Remotion能力。
- `ai_edit_v2_quality.py`：技术、内容、声音、布局和视觉质检。
- `ai_edit_v2_billing.py`：报价区间、上限预扣、实际结算和退款幂等。
- `renderers/shotstack_v2.py`：常规场景和最终时间线适配。
- `renderers/remotion_v2.py`：托管渲染任务、沙箱验证和结果适配。

AI生成代码永远不进入网站主服务器解释器、Node进程或文件执行路径。

## 9. HTTP API

### 9.1 用户接口

- `GET /api/v2/edit/capabilities`：返回入口、比例、语言、容量和当前能力开关。
- `GET /api/v2/edit/templates`：返回管理员已发布的平台模板。
- `GET /api/v2/edit/materials`：分页返回当前用户历史素材。
- `POST /api/v2/edit/uploads`：创建源媒体、必须素材或参考素材的COS直传签名。
- `POST /api/v2/edit/uploads/{id}/complete`：核验对象大小、MIME、归属和用途。
- `POST /api/v2/edit/quotes`：根据任务草稿返回价格区间、报价版本和有效期。
- `POST /api/v2/edit/jobs`：带 `Idempotency-Key` 确认报价、按上限预扣并创建任务。
- `GET /api/v2/edit/jobs/{id}`：只允许所有者查询队列、阶段、进度、报价、结算和结果。
- `POST /api/v2/edit/jobs/{id}/retry`：为允许重试的终态失败任务创建继任任务。

### 9.2 供应商接口

- `POST /api/v2/edit/webhooks/shotstack?token={secret}`。
- `POST /api/v2/edit/webhooks/remotion?token={secret}`。

Webhook随机密钥来自独立环境变量，使用常量时间比较。Nginx必须为回调路径关闭包含查询参数的访问日志，应用日志必须剥离token。回调体只用于提取供应商任务ID，最终状态必须主动回查。重复和乱序事件不得覆盖已完成终态。

## 10. 数据库设计

`ai_edit_v2.db` 至少包含：

### 10.1 `edit_v2_jobs`

保存所有者、创作入口、主输入、用户要求、模板版本、目标时长、比例、当前状态、排队时间、处理开始时间、时间预算、幂等键、报价、预扣、结算、导演方案、Render Graph、供应商任务、降级状态、输出COS键、错误、版本和时间戳。

### 10.2 `edit_v2_materials`

保存素材所有者、类型、用途、参考模式、语义标签、来源、COS对象键、MIME、尺寸、时长、质量指标、状态和内容摘要。数据库只保存COS对象键，不保存签名URL。

### 10.3 `edit_v2_job_materials`

保存任务、素材槽位、素材ID、优先级、必须标记、最终是否使用、排除原因和选用理由。完成任务时必须通过数据库约束或事务检查保证必须素材使用率100%。

### 10.4 `edit_v2_stage_attempts`

保存阶段、尝试次数、开始/结束时间、处理耗时、结果、错误码、供应商、模型、请求ID、计量、估算费用、重试和切换原因。

### 10.5 `edit_v2_provider_jobs`

保存供应商、能力类型、供应商任务ID、状态、是否主路线、是否降级、输入摘要和输出COS键。供应商任务ID一旦绑定不得替换为无关任务。

### 10.6 `edit_v2_provider_events`

保存Webhook事件指纹、供应商任务ID、归一化状态和接收时间，用唯一索引去重。

### 10.7 `edit_v2_quotes` 与 `edit_v2_billing`

保存报价版本、价格区间、预扣上限、实际结算、退差额、全额退款和唯一交易键。扣款、结算和退款均要求幂等。

### 10.8 `edit_v2_render_artifacts`

保存关键帧预览、Remotion片段、Shotstack成片、修复成片和最终成片的COS对象键、版本、校验结果和清理状态。

参考视频风格特征只保存在任务临时记录中，任务终态后清除，不进入用户风格库。

## 11. 状态机、并发与时间预算

正常状态：

```text
created
-> validating
-> quoting
-> precharging
-> queued
-> normalizing
-> transcribing
-> aligning_transcript
-> directing
-> resolving_assets
-> generating_assets
-> designing_audio
-> routing_render
-> rendering
-> assembling
-> quality_check
-> repairing
-> settling
-> storing
-> completed
```

`repairing` 仅在已有成片且质检指出明确可修复问题时进入，无修复需求可跳过。

失败状态按阶段区分，例如 `validation_failed`、`transcription_failed`、`director_failed`、`asset_failed`、`render_failed`、`quality_failed`、`settlement_failed` 和 `storage_failed`。

并发与时间规则：

- 第一阶段同时处理5至10个任务。
- 排队时间单独展示，不计入处理时长。
- 从 `normalizing` 开始计算正常处理时长，初始上限45分钟。
- 系统应按内容尽快完成，不以45分钟作为目标耗时。
- 已产生成片但质检失败时，可额外使用最多15分钟修复明确问题。
- 单任务处理总上限60分钟。
- 45/60分钟是初始运营参数，后续只能依据测试数据通过配置和版本记录调整。
- 超出时间预算且没有通过质检成片时进入失败并全额退款。

查询接口必须分别返回排队时长、处理时长、修复时长、当前阶段和剩余时间预算。

## 12. 媒体检测与标准化

源媒体从COS下载到任务专属临时目录后，FFprobe确认：

- 容器、视频流和音轨可解析。
- 时长大于0且不超过10分钟。
- 视频源至少有一个视频流；音频源至少有一个可用音轨。
- 真实类型与声明类型一致。
- 像素尺寸、帧率、编码、采样率和声道可读取。

视频容器、编码、时间基或帧率不适合下游时，FFmpeg标准化为MP4/H.264/AAC、30fps、48kHz。音频标准化为M4A/AAC、48kHz。保留源画面宽高比，最终画布由渲染层统一为1080p目标比例。

声音预处理可自动执行：

- 降噪。
- 去混响。
- 响度统一。
- 人声增强。
- 删除或削弱原视频中不合适的BGM。

预处理必须保留原始文件，结果不满意时可回退。标准化前后时长异常即失败，所有临时文件在终态后清理。

## 13. 内容重剪与目标时长

AI导演允许：

- 删除停顿、口误、重复和低信息片段。
- 在不改变原意和事实的前提下调整段落顺序。
- 根据用户目标时长进行语义压缩，而不是简单倍速。
- 在自然度允许范围内轻微调整语速。
- 当必须内容无法安全容纳时适当延长成片，并在结果中记录延长原因。

用户不填目标时长时，AI依据内容密度和表达完整性决定。用户填写目标时长时，它是导演约束而不是破坏内容的硬裁切命令。

### 13.1 实验性补录能力

“AI少量改写文案，并使用原人物克隆音色或通用配音补录”是实验性候选能力，后续可能重新判断是否进入正式范围。该能力默认使用功能开关隔离，不作为首轮稳定验收的硬依赖。

启用时必须满足：

- 只允许少量补句，不得改变品牌、产品、数字、价格和招商事实。
- 新音频优先使用B-roll、产品/门店素材、AI素材、图表或MG遮盖。
- 尽量避免人物正脸出现时播放补录音频。
- 不重新生成数字人口型画面，避免过长处理时间。
- 无法安全遮盖时缩短或取消补句。
- 补录不得造成明显人物口型不一致。

## 14. 文案、ASR与字幕

平台内生成的口播：

- 平台保存的原文负责语义和字符准确性。
- fun-asr负责分句、逐字时间戳和对齐锚点。
- 对齐模块执行确定性序列对齐。
- 品牌名、产品名、数字、价格和招商信息以原文为准。

外部视频/音频：

- fun-asr负责正文和时间戳。
- AI可修复标点和断句，但不得改变字符事实和原意。

字幕由AI根据内容、入口、模板和视觉密度决定是否启用及采用何种设计。字幕正文和时间轴由服务端确定性数据生成，AI不能重写准确文本。对齐覆盖率低于85%或时间无法单调映射时进入失败，不静默生成错误字幕。

## 15. `edit-plan 2.0` 中间协议

AI导演只输出平台协议，不输出COS键、签名URL、数据库ID、供应商API字段、任意HTML或任意网络地址。

顶层结构：

```json
{
  "version": "2.0",
  "creation_mode": "natural_brief",
  "duration_ms": 44920,
  "target_duration_ms": 40000,
  "aspect_ratio": "16:9",
  "language": "zh-CN",
  "editorial_decisions": [],
  "style_system": {},
  "scenes": [],
  "overlays": [],
  "materials": [],
  "caption_plan": {},
  "audio_plan": {},
  "delivery": {"resolution": "1080p", "format": "mp4"}
}
```

每个场景至少包含：

```json
{
  "id": "scene_01",
  "start_ms": 0,
  "end_ms": 5800,
  "intent": "打破美业暴利认知",
  "source_ranges": [{"start_ms": 1200, "end_ms": 7000}],
  "layout_intent": "speaker_with_diagnostic_chart",
  "visual_type": "diagnostic_hook",
  "headline": "美业真的赚钱吗？",
  "material_slots": ["slot_01"],
  "motion_graphics": [{"type": "comparison_chart", "data_ref": "fact_01"}],
  "transition_intent": "hard_emphasis",
  "complexity": "advanced"
}
```

语义素材槽位：

```json
{
  "slot_id": "slot_01",
  "start_ms": 1200,
  "end_ms": 4200,
  "semantic": "美容门店经营压力",
  "recommended_visual": "冷清门店和账本特写",
  "kind": "image_or_video",
  "required": false,
  "generation_allowed": true,
  "generation_intent": "写实商业场景"
}
```

`audio_plan`描述BGM情绪、节奏、歌词政策、对白避让、转场音效和重音音效语义，不包含供应商或文件URL。字幕正文不由AI导演输出，导演只能输出字幕样式和强调索引。

服务端校验时间、场景覆盖、素材引用、事实字段、布局白名单、MG数据来源和声音策略。原始导演方案保持不可变，素材解析和渲染路由生成独立的 `resolved_plan` 与 `render_graph`。

## 16. 模板、风格与自由布局

V2不限制为固定三种风格。风格来自：

- 用户自然语言要求形成的任务风格系统。
- 管理员发布的平台模板。
- AI开放生成的任务专属视觉系统。

平台模板必须参数化以下维度：

- 场景数量和时长。
- 分镜与素材占比。
- 单栏、双栏、画中画、拼贴、图表、清单和重点卡布局。
- 字幕密度与强调方式。
- 色彩、字体和信息层级。
- 动画节奏、镜头运动和转场强度。
- BGM情绪、节拍密度和音效策略。

同一模板处理不同内容时必须产生结构差异。只换颜色、标题或图片位置但时间线和信息结构相同，判定为“伪多风格”，不通过验收。

项目包中的优秀Remotion/Shotcraft成片作为首批视觉基准。接入前必须提取可复用组件、参数、字体授权、素材依赖和渲染约束，不直接复制强绑定单片内容。

## 17. 素材解析与全类型生成

素材槽位按四级固定优先级解析：

1. 当前任务用户素材：先满足“必须使用”，再考虑标记“可直接使用”且质量合格的参考素材。
2. 当前用户历史素材库。
3. 平台公共素材库。
4. AI生成素材。

AI可生成：

- 图片。
- 短视频。
- 图标和插画。
- 动态图表所需数据表现资产。
- BGM。
- 转场音效。
- 重音音效。

解析器负责 `slot_id -> source -> asset_id -> cos_key`，AI导演不能选择具体数据库ID。必须素材使用率100%；参考素材可因质量排除。所有生成素材必须先校验、上传私有COS、入库并关联任务，提交渲染前才生成短期签名URL。签名URL不得写入数据库、日志或AI上下文。

## 18. 自动渲染路由

渲染路由根据场景复杂度、布局、动画、内容类型、模板能力、供应商状态、价格上限和剩余时间自动决定，不让用户选择渲染器。

路由原则：

- 常规字幕、基础卡片、B-roll和标准转场优先Shotstack。
- 复杂MG、动态图表、编辑拼贴、自由布局和AI动画代码使用隔离Remotion。
- 一个视频可以逐场景混合两种能力。
- Remotion片段统一输出目标比例、分辨率、帧率和色彩规格。
- Shotstack负责最终时间线编排；FFmpeg只做确定性标准化、后处理、拼接兜底和质检，不承担AI自由代码执行。

每次路由记录能力、供应商、模型、预计费用、预计耗时和理由。路由变更或供应商切换必须记录原因。

## 19. Remotion自由代码安全

AI生成动画代码只能在隔离云函数或托管渲染沙箱执行，必须满足：

- 依赖白名单和锁定版本。
- 禁止安装任意依赖。
- 禁止 `eval`、动态进程、Shell和任意原生扩展。
- 文件系统仅允许任务临时目录，终态后销毁。
- 网络默认关闭；仅允许读取任务授权的短期COS地址和必要平台资源域名。
- CPU、内存、并发、输出大小和渲染时间硬限制。
- 静态语法、AST、依赖、资源引用和危险API校验。
- 在完整渲染前生成关键帧预览。
- 自动检查文字重叠、越界、安全区、人脸/产品/Logo/二维码裁切和动画完成状态。

自由代码失败后，AI可根据明确错误自动修复最多2次。仍失败时降级到风格相近的稳定模板。任务记录 `open_generation_failed`、修复次数、降级模板和原因，统计开放创作降级率。

## 20. BGM、音效与声音设计

BGM由AI生成，不依赖用户自带版权不明音乐。

规则：

- 人声主导视频只使用无歌词音乐。
- 纯视觉内容由AI决定是否允许人声或歌词，并记录决定。
- 根据语义转折、镜头切换和MG重点自动生成或匹配转场音效与重音音效。
- 所有BGM和音效执行对白避让和自动ducking。
- BGM和音效不得遮盖对白、品牌、数字、价格和关键信息。
- 原视频已有不合适BGM时允许删除或削弱。
- 音频处理记录响度、峰值、降噪和避让参数。

声音质检失败时优先重新混音，不重新生成整个画面；修复仍受总时间和预扣上限约束。

## 21. 供应商与自动切换

ASR、导演模型、图片、短视频、BGM、音效、Shotstack和Remotion能力通过统一Provider接口调用。允许配置主备供应商，但自动切换必须同时满足：

- 不突破用户确认的预扣上限。
- 不突破45/60分钟时间预算。
- 不降低内容硬门槛。
- 输入和输出协议兼容。

每次调用保存供应商、模型、费用、耗时、重试次数和切换原因。模糊的提交超时不得盲目重复创建可能收费的供应商任务，必须先通过任务ID、幂等能力或供应商查询确认。

## 22. 动态报价与结算

提交前展示价格区间。报价因素至少包含输入时长、目标时长、必须素材数量、预计生成图片/视频、BGM和音效、MG复杂度、渲染路线和修复预算。

单价和系数来自管理员维护的版本化价格表，不散落硬编码在各Provider中。报价响应分项返回基础剪辑、素材生成、声音生成、渲染和修复预算，并同时返回最低价、预扣上限、价格表版本和报价有效期；任务创建后始终使用已确认的价格表版本。

计费流程：

```text
生成报价区间
-> 用户确认
-> 按上限预扣
-> 内部执行与重试
-> 质检成功后按实际平台计费规则结算
-> 退还差额
```

规则：

- 内部重试不重复扣费。
- 主备供应商切换不得突破预扣上限。
- 实际成本达到上限时必须降级、减少非必须生成或失败退款，不得静默追加扣费。
- 未交付通过质检的成片则全额退款。
- 扣款、结算、退差额和全额退款均使用唯一交易键和条件更新实现幂等。
- 报价和计费规则必须版本化，任务保存当时版本。

## 23. 失败、修复、降级与恢复

- 结构化导演方案首次不合法时允许修复一次。
- 普通网络读取和状态查询按能力执行有限指数退避。
- 供应商提交结果不确定时禁止直接重复收费提交。
- 已取得供应商任务ID的任务重启后继续查询原任务。
- 已完成的ASR、素材生成、BGM、音效和Remotion片段可从持久化检查点复用。
- 已产生成片但质检失败时，额外15分钟只修复明确问题。
- 开放生成最多自动修复2次，仍失败降级到稳定模板。
- 终态失败任务全额退款。
- 用户再次发起时创建继任任务和新报价，不复活旧计费事务。

## 24. 成片质检

### 24.1 内容硬门槛

- 必须素材使用率100%。
- 品牌名、产品名、数字、价格和招商信息不得篡改。
- 字幕与语音一致。
- 补录不得造成明显人物口型不一致。
- 语义重剪不得改变原意或事实。

### 24.2 画面与技术硬门槛

- 无黑帧、卡帧、缺图、花屏、错误占位和未完成动画。
- 人脸、产品、Logo、二维码和文字不得错误裁切。
- 无文字重叠、越界和安全区问题。
- MP4可以完整解码。
- 输出为1080p、正确比例、有音轨、时长合理。
- COS地址可播放、可下载。

### 24.3 声音硬门槛

- 对白清楚。
- 无异常静音和爆音。
- BGM和音效不压人声。
- 关键信息处对白可懂度达标。

### 24.4 创意八维评分

每条成片按以下八维评价：

1. 内容匹配。
2. 结构差异。
3. 信息层级。
4. 动画质量。
5. 节奏。
6. 声音设计。
7. 视觉完成度。
8. 技术质量。

测试阶段先由视觉模型评分，再由人工抽检校准。模型评分不能替代技术硬门槛。初始建议采用5分制，成功样本平均分不低于4分且任一维度不低于3分；人工校准发现系统性偏差时必须更新评分提示词和版本记录。

## 26. 安全与隐私

- 所有源资产和用户素材按账号校验归属。
- 普通用户不能上传代码、模板包或发布公共模板。
- AI代码只在隔离沙箱执行。
- 数据库只保存COS对象键，不保存签名URL。
- 签名URL只在使用前短期生成。
- 日志禁止记录密钥、完整文案、签名URL、用户素材内容和供应商完整响应。
- 参考视频风格特征任务结束后清理。
- 管理员模板发布属于高风险操作，必须二次确认并保留审计记录。
- 内容安全审核仍不属于本阶段，但结构安全、代码安全、账号权限和文件安全必须实现。
