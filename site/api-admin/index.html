二、音频模块接口（content_api.py · 8096）

接口方法用途关键参数返回 / 后续动作
生成配音
/api/gen/audio		 POST 提交 TTS 异步任务。公共音色走 OpenAI TTS；个人复刻音色 S_* 走豆包 TTS。 text 文案，最多 1200 字
voice：dapeng/zelong/paul 或 vip_S_xxx
speed 0.5-2.0，pitch -12-12，volume -50-100		 返回 job_id，轮询 GET /api/gen/job/{id}。完成后 result 内有 url，同时写入配音资产。
查询音色
/api/gen/audio/voices		 GET 读取当前用户可用音色。公共音色所有用户可用，个人音色只返回本人。 无 返回 audio_voices 列表：scope、voice_key、provider_voice、preview_url。
配音资产
/api/gen/audio/assets		 GET 读取音频模块生成的配音资产。 limit，默认 120，最大 120 返回本人 audio_assets：音频 url、文案、音色、语速、音调、音量。
我的音色槽位
/api/gen/audio/slots		 GET 读取当前用户购买/兑换到的个人音色槽位和复刻状态。 无 返回 audio_voice_slots，包含 status、reclone_count、preview_url、错误信息等。
兑换槽位
/api/gen/audio/redeem-slot		 POST 输入兑换码，从槽位池分配一个未使用的豆包复刻槽位。 code 兑换码 返回分配后的槽位记录。槽位 id 只用于后端流程，前端不直接展示给用户。
VIP 复刻上传
/api/gen/audio/clone-vip		 POST 用槽位 id + 用户上传样音发起豆包声音复刻。后端立即标记 training，并在后台上传豆包。 slot_id，name，audio base64，audio_format 如 wav/mp3 返回 training。前端继续轮询 /api/gen/audio/clone-status，等待复刻完成并生成试听音频。
查询复刻状态
/api/gen/audio/clone-status		 GET 查询豆包复刻状态。豆包返回本次新结果后，后端再用测试文案生成试听音频，并更新卡片状态。 slot_id status=ready 且有 preview_url 才代表完整流程结束；failed 时看 clone_error。
完整流程：前端拿音色/槽位 → 生成配音时提交 /api/gen/audio → 轮询任务 → 文件进 content_out，资产进 audio_assets.db。复刻流程：兑换槽位 → 上传样音 → 等豆包训练成功 → 生成测试音频 → 更新 audio_voices.preview_url 和槽位状态。
